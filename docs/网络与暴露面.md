# 网络与暴露面 —— 现在到底开了什么、连了什么、谁看得到什么

这份是**现状说明**，不是设计提案。所有结论都能在代码里核对，引用的位置写在每条后面。

一句话：**默认模式不过公网；五个模式里有三个一个入站端口都不开。**
唯一真的把端口摆到公网上的，是 UPnP 开洞 —— 它**必须显式允许**才试，默认不试。

## 一、五个模式，各自做了什么

模式常量在 `server/src/modes.mjs:78-90`：

```js
export const MODE_AUTO        = 'auto'      // 默认
export const MODE_LAN         = 'lan'
export const MODE_TUNNEL      = 'tunnel'
export const MODE_RELAY       = 'relay'
export const MODE_CLOUDFLARED = 'cloudflared'
export const MODES = [MODE_AUTO, MODE_LAN, MODE_TUNNEL, MODE_RELAY, MODE_CLOUDFLARED]
export const LOOPBACK_MODES = new Set([MODE_TUNNEL, MODE_CLOUDFLARED])   // modes.mjs:96
```

`LOOPBACK_MODES` 这个集合是理解全局的钥匙：**隧道模式和 Cloudflare 模式被归为同一档 —— 两个都只听本机回环。**
注意 **`auto` 不在里面** —— 它要绑 `0.0.0.0`，因为「局域网直连」那一格全靠它（`modes.mjs:585-590` 专门写了理由）。

监听地址由它算出来（`modes.mjs:470`，写进 `baker.env` 的是 `modes.mjs:543`）：

```js
const hostWanted = LOOPBACK_MODES.has(effectiveMode) ? '127.0.0.1' : '0.0.0.0'
```

| 模式 | 监听在哪 | 入站防火墙规则 | 公网能主动连进来？ | 出网连到哪 |
|---|---|---|---|---|
| **Auto**（默认） | `0.0.0.0` | 建 1 条，**只放 Private**（和 Lan 同） | 取决于阶梯走了哪一格 | 视情况 |
| **Lan** | `0.0.0.0` —— 所有网卡 | 建 1 条，**只放 Private** | **不能**（被路由器挡在外面） | 不连出去 |
| **Tunnel** | `127.0.0.1` —— 只有本机 | **一条都不建**，还会把旧的删掉 | **不能** | 主动出站连你的中继 |
| **Relay** | `0.0.0.0` | 建 1 条，**放行 any** | **能** —— 但这台就是你自己的中继机，本来就该有公网地址 | 不连出去 |
| **Cloudflared** | `127.0.0.1` —— 只有本机 | **一条都不建**，还会把旧的删掉 | **不能** | `cloudflared` 主动出站连 Cloudflare |

### Auto 的阶梯：谁最省依赖，谁先上

`auto` 不是一个「网络位置」，它是一串**依次尝试**（`modes.mjs:565` 的 `runAutoLadder()`）：

| 顺序 | 那一格 | 依赖谁 | 什么时候赢 |
|---|---|---|---|
| 1 | **局域网直连** | 谁也不依赖 | 客户端和服务器在同一个网里 |
| 2 | **路由器开洞（UPnP）** | 路由器配合（很多默认关着） | 外面的人够不着、但路由器肯开洞 → **不经任何第三方** |
| 3 | **Cloudflare 兜底** | Cloudflare | 前两格都不成 |

**UPnP 那一格必须显式允许才试**（`-AllowUpnp` / 管理页勾选框 / `BAKER_UPNP=1`）。
理由是它会真在公网上开一个端口，不该由程序替用户默认决定。不许的时候 auto = 局域网 + Cloudflare，照样零入站端口。

失败的原因会**原样打出来**（`server/src/index.mjs` 的 `startAutoLadder()`）—— 那句「路由器那条走不通 —— 没有找到支持 UPnP 的路由器……」是用户唯一能拿去做点什么的信息。

### 防火墙到底建了什么

在 `modes.mjs:400-425`。归到 `LOOPBACK_MODES` 的那两个模式走这一段：

```js
if (LOOPBACK_MODES.has(mode)) {
  for (const m of [MODE_LAN, MODE_RELAY]) {
    try { run(['advfirewall', 'firewall', 'delete', 'rule', `name=${firewallRuleName(port, m)}`]) }
    catch { /* 本来就没有 */ }
  }
  return { ok: true, elevated: true, hint: null, name: null }
}
```

**不只是「不新建」，还会主动把以前开的删掉。** 从 Lan 切到 Cloudflared，那条 `BAKER 聊天服务器` 规则会被删掉。

剩下两个模式建的规则（`modes.mjs:418-423`）：

```js
const profile = mode === MODE_RELAY ? 'any' : 'private'
run(['advfirewall', 'firewall', 'add', 'rule',
     `name=${name}`, 'dir=in', 'action=allow', 'protocol=TCP', `localport=${port}`, `profile=${profile}`])
```

`profile=private` 不是随手选的，代码里 `modes.mjs:416-417` 专门写了理由：

> Lan 只放 Private：服务器要是被插到「公用」网络，这条不生效、端口就是关的。
> 这是有意的，别改成 Any —— 那等于把一台家用机器直接摆到公网上。

也就是说：**Lan 模式下把笔记本插到咖啡厅 WiFi（被识别成「公用」），端口自动是关着的。**

## 一之二、IPv6：不用第三方，但要说清楚代价

一台有**全局 IPv6** 的服务器可以被直接连上 —— IPv6 没有 NAT，不需要中继、不需要隧道、不需要任何第三方（DNS 除外）。

代码里的支持位置：

- `classifyAddress`（`modes.mjs:141`）把全局单播地址归成 `lan`（因为对这台机器而言它就是一条**不经中介就能用**的地址）；`fe80::` 链路本地归成 `apipa`（和 `169.254.x.x` 同类，只在本地链路有意义，不能给人填）。`fc00::/7` 私有段（含 `fd00::` 的 Tailscale）仍然按原来的分类。
- `listAddresses`（`modes.mjs:203`）现在**同时收 v4 和 v6**，带上 `family` 字段；跳过 `fe80:` 和带 `%` 的 zone id（后者写进 URL 会坏掉）。排序把 v4 放前面，v6 放后面。
- **拼 URL 必须加方括号**：`urlHost()`（`modes.mjs:201`）。
  `ws://240e:982:3201:3:9b::2a5:8787/ws` 里的冒号会被当成端口分隔符，是个**语法上就坏掉的 URL**。`[240e:982:3201:3:9b::2a5]` 才是对的。这条在开发机上通常测不出来（开发机大多没有全局 IPv6），所以 `server/test/modes.mjs:201-236` 专门为它写了一节，`tools/mutation-check.ps1` 的变异 Q 也钉着它。

### ⚠ 两个必须先知道的前提

1. **服务端没有 TLS。** `server/src/index.mjs` 里是个裸的 `createServer`，从来不提供 `wss://` —— 之前用到的 `wss://` 是 **Cloudflare 帮你终结的**。所以 IPv6 直连只能用 `ws://` 明文：
   - 聊天正文/图片**仍然安全**（端到端加密，见下一节）；
   - 但 **auth 帧是明文 JSON**，`token` / `selfId` / 显示名会在这条链路上裸奔（见下一节那张表）。
   要直连又不想这样，就得给服务端配 TLS（自己的域名 + `AAAA` 指向那个 IPv6 + Let's Encrypt **DNS-01** 挑战，不用开 80 端口），变成 `wss://baker.域名:8787/ws`。这样只有 DNS 被问了一次。
2. **云主机的安全组在机器外面。** DNS 后缀是 `openstacklocal` 这类云主机，前面通常还有一层**云平台安全组**（OpenStack / 阿里云 / 腾讯云的控制台里配的），机器内部的 Windows 防火墙怎么设都管不到它。放行 8787/TCP 得去控制台点。
   验证办法：从**任何**有 IPv6 的机器（手机热点就够）跑 `Test-NetConnection <那个IPv6> -Port 8787`。

**IPv6 是阶梯里新增的一格，不是替换别的格** —— 客户端所在网络也必须有 IPv6（国内手机 4G/5G 基本有，公司/学校网络经常没有）。

## 一之三、把地址传到别的机器（二维码 + 可复制串）

服务器和客户端常常不在同一台机器旁边，而**地址会变**（Cloudflare 兜底那条每次重启都换一个）。

管理页上有一张卡片负责这件事（`server/admin.html` 的 `#shareCard`），背后的数据是 `GET /api/share`（函数本身在 `server/share-link.mjs`，服务端与客户端共用）：

```js
export function shareTextFor({ address, token, origin = '' }) {
  const url = new URL(origin || 'http://127.0.0.1')
  url.searchParams.set('server', address)
  if (token) url.searchParams.set('token', token)
  return url.toString()
}
```

它给的这条链接，客户端本来就认 —— `src/config.ts` 的 `applyUrlOverride()` 一直支持 `?server=…&token=…`（只对本次打开生效，不写 localStorage）。所以**不需要任何新协议**。

五样东西一起给：

| 给的 | 干什么用 |
|---|---|
| **二维码**（网页上是 SVG） | 手机扫一下就用这条地址打开客户端，一个字符都不用手敲 |
| **「下载二维码（PNG）」** | 存成文件发出去。网页上画的是 SVG（`server/qr.mjs`），下载走 `server/src/png.mjs` —— 只依赖 `node:zlib` 的灰度编码器 |
| **可复制串** | 发微信/短信过去，对方粘贴 |
| **客户端里的「粘贴一条连接串」** | 收到以后粘进设置面板，自动拆出地址和口令（`src/share.ts` 的 `parseShareText()`） |
| **客户端里的「上传二维码图片」** | 只有一张截图/照片时用（转发来的、拍屏幕的），把图丢进去就地认码（`src/qr-scan.ts` + jsqr） |

**客户端自己也能生成同一张码**（`src/components/AnnouncementsPanel.tsx` 的「下载邀请二维码（PNG）」），走 `GET /api/join`。**两个入口的鉴权门槛故意不同**：

| 入口 | 谁的门 | 为什么 |
|---|---|---|
| `GET /api/share` | **管理口令** | 它就在管理页上，旁边全是管理接口 |
| `GET /api/join` | **聊天口令** | 「把码转给还没连上的朋友」本来就是成员要做的事。`/api/join` 放在管理口令闸门**之前**，`adminToken` 它压根不看 |

这不构成提权：那条码里装的（地址、聊天口令）本来就发给每一个成员了。两个入口共用同一个 `shareTextFor()`，所以串**一定一模一样** —— 不共用迟早会出现「管理页扫得出来、客户端下载的扫不出来」这种最难查的分歧。

客户端下载的 PNG 是**本地 canvas 画的**（`toBlob`），不经过服务器；`server/qr.mjs` 那份编码器是纯 ESM、零依赖，浏览器直接 import 就行。它只在 `tokenEnabled` 时才出现 —— 只带地址的码对新朋友没用。

二维码是**本地生成**的（`server/qr.mjs`，零依赖，byte 模式 + 纠错等级 M + 版本 1~20），**不走任何在线图片服务** —— 那条串里可能有口令，不该发到别人服务器上去画图。认码也一样在客户端本地做（jsqr，零依赖），图片不上传。

⚠ **口令默认不放进二维码**。那张卡片是给「传地址」用的，而口令是另一件事；默认让一个可能被拍屏、被转发的东西里不含口令。例外只有一个用户看得见的开关：

- 管理页卡片上「二维码里带上聊天口令」的勾选框 —— `POST /api/share` `{enabled}` → `modes.setShareToken()` → `writeEnv(baker.env, { BAKER_SHARE_TOKEN: '1' | null })`（**关掉是删键，不是写 0**）。当场生效、状态看得见、重启还在。
- 启动参数 `--share-token` / `BAKER_SHARE_TOKEN=1` —— 装的时候就定好，之后仍可用勾选框改。

为什么不让用户手改 `baker.env`：手改出来的状态在页面上看不见，而这是个**安全开关** —— 忘了「开过」比忘了「关掉」糟得多。`/api/share` 用 `tokenIncluded` / `tokenEnabled` / `tokenCanBeEnabled` 三个字段把状态说全，勾选框**以服务器为准**。

### 解析那条串时，认不出来必须说

`parseShareText()`（`src/share.ts`）的规矩：**只认 `ws://` / `wss://`，认不出来就报错，绝不猜一个地址出来。**

这条不是洁癖。「粘错了」的症状是**连不上**，和「网不通」「口令不对」长得一模一样；如果解析器再顺手猜一个，用户就彻底没有线索了。所以：

- 带壳的（两端引号、尖括号、中文引号、书名号）、首尾有空白的、末尾多一个中文句号的 —— 都剥掉再解析；
- 漏了 `/ws` 的（手敲地址最容易漏）—— 自动补上；
- 光一个 `http://…/admin` 网页地址 —— **明确拒掉**，并说「这是网页地址，不是客户端要填的」，而不是把网页地址填进设置；
- 只给了地址没给口令 —— 返回 `token: null`，**调用方保持原口令不动**（顺手清空等于修好一半、弄坏另一半）。

`tools/share-probe.ts`（28 项）钉的就是上面这几条。

## 二、谁看得到什么

这是最容易被误解的一段，所以把边界画清楚。

### 聊天正文：中间谁都打不开

消息在客户端加密，服务器和中继搬的是密文（`src/crypto/envelope.ts:1-16`）：

```
明文 ──AES-256-GCM(会话密钥, 随机IV, AAD)──> { iv, ct } ──> 服务器 ──> 收件人
                                                              ↑
                                                    服务器只搬这坨字节，
                                                    它没有会话密钥，所以打不开。
```

会话密钥是 X25519 协商 + HKDF 派生的（`envelope.ts:39-42`）。中继模块自己也是这么声明的（`server/src/relay.mjs:11-16`）：

> 一条也看不见。消息是端到端加密的（见 src/crypto/），中继看到的是密文；
> 它知道的是「有个客户端连过、大约几点了、发过多少字节」——和服务器本来就能看到的元数据一样多。
> 所以中继可以放在任何一个便宜的 VPS 上、可以跟别人合用，不需要信任它。

### 但有几样东西是明文过线的 —— 这一条值得知道

客户端连上之后发的第一帧是**普通 JSON**，不是密文（`src/websocket.ts:445` 和 `:459`）：

```js
this.writeFrame({ op: 'auth', token, selfId, name, avatarKey })
this.writeFrame({ op: 'auth', token, selfId, name, avatarKey, ed: pub.ed, x: pub.x })
```

所以**谁终止了 TLS，谁就能看到**这些字段：

| 字段 | 是什么 |
|---|---|
| `token` | 共享口令（`server/src/index.mjs:562` 拿它比对：`frame.token !== requiredToken` → 口令不对） |
| `selfId` | 你的用户 ID |
| `name` | 显示名 |
| `avatarKey` | 头像标识 |
| `ed` / `x` | 你的 Ed25519 签名公钥 / X25519 协商公钥 |

在 **Tunnel / Relay / Cloudflared** 三种模式下，终止 TLS 的就是中间那台机器（你的中继，或者 Cloudflare）。**它们看得到上面这几个字段，看不到消息正文。**

要不要为这个做点什么，是个取舍，不是 bug：

- `ed` / `x` 是公钥，本来就该公开。
- `token` 是共享口令。拿到它的人能通过第一道门，但**冒充不了已登记的身份** —— 身份靠的是签名挑战（`index.mjs:410-436` 的 `finishAuth`），验的是「持有私钥」，不是「知道一个字符串」。不过新身份是 TOFU（首次使用即信任，`index.mjs:438-443`），所以拿到口令的人可以登记一个**新**身份混进来。
- 想彻底不暴露它，办法是别让中间人终止 TLS（比如客户端和服务器之间自己再套一层），但那是要动客户端和服务端的改动。

## 三、那三个"第三方"分别是谁

| 模式 | 经手的机器 | 它能看到 | 它看不到 |
|---|---|---|---|
| Lan | 没有第三方 | —— | —— |
| Tunnel | 你自己建的中继（`--relay`） | 上面那张表里的字段 + 流量大小/时间 | 消息正文 |
| Relay | 同上，就是本机 | 同上 | 消息正文 |
| Cloudflared | **Cloudflare 的机器** | 同上 | 消息正文 |

Cloudflared 和 Tunnel 的差别只在**谁提供那台跳板**：Tunnel 是你自己的一台机器（要你自己有公网地址），Cloudflared 是 Cloudflare 免费提供、代价是地址每次重启都变。两者都**零入站端口**。

> **那个「每次重启都变」是可以不要的。** 换成**命名隧道**（在 Cloudflare 后台建隧道 + 挂一个有 `zone` 的主机名，把凭据和主机名交给安装脚本），地址就固定成 `wss://<你的主机名>/ws`。它**仍然要你自己有一个域名** —— Cloudflare 的 Public Hostname 必须挂在一个 zone 上。所以「不花钱、不用域名、地址还固定」这条路不存在；要免域名又要固定地址，只能用自己那台中继（Tunnel）。

## 四、几个常见误解

**「是不是一定要暴露公网？」**
不是。五个模式里只有 Relay / Lan / Auto 建入站规则，而它们都**不出路由器**（Lan 只放 Private，Relay 是你自己的公网机器）。Tunnel 和 Cloudflared 连一条规则都不建。
Auto 唯一可能真的把端口摆到公网上的情况，是**你显式允许了 UPnP 而且路由器配合** —— 那一格赢了的话就是直连，也正是它省掉第三方的原因。不许 UPnP 时 auto 和 Cloudflared 一样零入站端口。

**「状态页说的『暴露面』是 BAKER 开的口子吗？」**
不是。那是 `status.ps1` 在**检查并报告**机器上有没有别的程序开了口子 —— 那种「任意程序 + 任意端口 + 含 Public」的规则才是真危险。BAKER 自己的规则是单独归类的。

**「UPnP 是第五种模式吗？」**
不是。它是一种**开洞动作**，Auto 模式会（在允许时）试一遍，管理页上也能单独按。按下去会在路由器上加一条真实的端口映射，**洞是真的开在公网上的** —— 这也是为什么它不跟模式自动走，得手动确认。

**「换成 Jami / Keet 是不是就不依赖第三方了？」**
不是。Jami 靠公共 bootstrap 节点（`bootstrap.jami.net:4222`）找节点；Keet 用的 HyperDHT 同样有一组硬编码的公共 bootstrap 节点（`node1/node2/node3.hyperdht.org:49737`，见 [holepunchto/hyperdht](https://github.com/holepunchto/hyperdht)）。两个都需要公共基础设施来互相发现。而且它们不是能嵌进来的库 —— 用 Jami 就等于不用 BAKER 了。

## 五、想更少依赖，物理上还剩什么

两台互相找不到的机器要连上，只有三条路：

1. **有公网中继**（Tunnel / Relay / Cloudflared 走的就是这条）
2. **有虚拟组网**（Tailscale / ZeroTier —— 把两台机器放进同一个虚拟局域网，然后当 Lan 模式用）
3. **路由器上开个洞**（UPnP，或手工端口映射）

第四条不存在 —— 这不是实现选择，是 NAT 的算术：找不到的地址，没有任何协议能凭空连上。

**但如果服务器本身有全局 IPv6，就多了一条真正「不用任何人帮忙」的路**（见上面「一之二」）—— IPv6 没有 NAT，服务器监听好、安全组放行就能直连。代价是要自己解决 TLS（否则 auth 帧明文过线）。

在这三条里，**依赖最少的是第 2 条**：组网由 Tailscale/ZeroTier 负责，BAKER 自己在局域网里跑，一个端口都不用对外开，也不经过任何聊天中继。

想连 Cloudflare 也不用，就只剩「自己有一台公网机器当中继」这一条 —— 机器还是公网的，只是从 Cloudflare 的换成你的。

### 顺带一句：地址传不过去，和「连不上」是两件事

上面整段讲的是**怎么到达**。还有一类问题长得一模一样、原因却完全不同：**地址本身没传到对方手里**（或者传过去的时候被转录错了）。
Cloudflare 兜底那条每次重启都换地址，服务器又常常不在手边 —— 这就是管理页那张「把地址传到别的机器」卡片存在的原因（见「一之三」）。
它解决的不是网络，是**人和人之间那一跳**。
